# UC-0006-receive-message

## Actor
- Пользователь получатель

## Goal
- Я как пользователь хочу получать новые сообщения от другого пользователя

## Preconditions
- Текущий пользователь зарегистрирован
- Текущий пользователь не заблокирован

## Trigger
- Текущему пользователю отправили новое сообщение

## Happy Path
1. Система получает новое сообщение
2. Система определяет какому чату принадлежит сообщение
3. Система обновляет состояние нужного чата
4. Система уведомляет пользователя о новом сообщении в чате

## Alternative Path 1
- В данный момент ни один чат не открыт
1. Система сообщает пользователю, что в конкретном чате пришло новое сообщение
2. В списке чатов в конкретном чате увеличивается счетчик непрочитанных сообщений или появляется впервые

## Alternative Path 2
- В данный момент открыт чат А, а новое сообщение пришло в чат Б
1. Состояние чата А не меняется
2. В списке чатов в чате Б увеличивается счетчик непрочитанных сообщений или появляется впервые

## Alternative Path 3
- В данный момент открыт чат в который пришло новое сообщение
1. Сообщение добавляется в чат
2. Сообщение считается сразу прочитанным
3. Счетчик непрочитанных сообщений текущего чата не изменяется

## Failures

### Failure 1
- Некорректное сообщение
1. Состояние чатов не изменяется

## Postconditions
1. Текущий пользователь узнаёт о новом сообщении

## Business rules
- нет

## Open questions
- Если в текущий чат пришло новое сообщение оно сразу считатеся прочитанным? А если вкладка браузера в фоне, а если пользователь читает прошлые сообщения и не видит новое?
- Как уведомить пользователя, что у него есть непрочитанные сообщения в другом чате?
- Нужно ли сортировать список чатов по дате получения новых сообщений? Будет ли текущий открытый чат с прочитанными сообщениями сверху или нужно сортировать только чаты с непрочитанными сообщениями?
